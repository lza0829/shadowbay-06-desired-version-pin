# 影湾 Shadowbay

系统与底层 · IoT 开发底座。

- 前端 http://127.0.0.1:7100
- 接口 http://127.0.0.1:12100

```powershell
docker compose up -d --build
```

本机开发：

```powershell
# 后端
cd backend
pip install -r requirements.txt
$env:预置目录 = (Resolve-Path ..\fixtures)
uvicorn app.main:app --reload --port 12100

# 前端
cd frontend
npm install
npm run dev
```

## 期望版本钉

解决“指令在途时期望改版，送达后有的按旧版执行、有的漂到新版”。每条新令都留下可核的期望版号与载荷快照（禁止只存动作名），并与影子台 `期望版本史` 同票。

两条互斥取版路径：

- **钉版（默认）**：下发时在事务内钉住当前期望，廊行保存 `钉住期望版 / 期望快照 / 快照核(sha256) / 版源=下发时钉版`；在线直达立即按快照执行，离线令重连补投时校验快照哈希与版本史同票后按快照执行。
- **读最新**：廊行只存动作（钉住版为 0、无快照），送达/补投当下在事务内读取当前期望，并回填 `执行期望版 / 执行载荷 / 版源=执行时读最新`。

核验口（返回 `令号 / 钉住的期望版 / 当前期望版 / 执行载荷 / valid` 等字段，另有中英文别名字段）：

```bash
curl "http://127.0.0.1:12100/期望版本钉/核验?令号=CMD-xxxx"
# 别名：/期望版本钉/verify?令号=...  /核验?令号=...
#       /期望版本钉/令号/{cmd}/核验  /指令廊/{cmd}/核验
```

页面：导航「版本钉」为专页（场景演练 + 令册钉版列⇄当前期望版同屏对照 + 按令号回翻）；影子台高亮每台设备被钉住的版本，指令廊同样同屏对照并可回翻；`/对影验` 始终以**当前期望**判齐，版漂只计数、不判失败，仅真正钉版异常（缺快照/篡改/哈希不符/版本史不同票/执行漂版）才判未过。

并发失败闭：期望写入支持 `前置期望版` CAS；下发支持 `基于期望版` 基准校验；改期望与补投均在 `BEGIN IMMEDIATE` 事务内进行，补投时快照被篡改或与版本史不同票则回滚并返回 409，令留在途。

自动化与测试：

```bash
# 后端 pytest（钉旧版 / 读最新对照 / 并发失败闭，共 14 例）
cd backend && python -m pytest

# 真实 HTTP 端到端：v1→离线→钉版下发→抬 v2→重连补投，
# 另含读最新对照、在线直达钉版版源断言（33 条断言，仅用标准库）
python 自动化/版本钉_离线抬版再补投.py
# 可指定地址：SB_BASE=http://127.0.0.1:7100/api python 自动化/版本钉_离线抬版再补投.py
```

一键场景接口：`POST /期望版本钉/场景/钉旧版`、`POST /期望版本钉/场景/读最新`、`POST /期望版本钉/场景/并发失败闭`。
